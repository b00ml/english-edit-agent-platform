## 2. 受限完整Trace快照

### 2.1 摘要与私有载荷分离

TraceLog仍只存脱敏/截断摘要、费用、usage、stage、attempt、模型身份。新增TraceSnapshot表：trace_row_id外键、Fernet加密ciphertext、密文字节数、脱敏内容SHA-256、replay_level、expires_at；TraceLog新增snapshot_status。

[trace_snapshots.py](../../backend/app/engine/trace_snapshots.py)在调用完成后立即封存实际发送的messages和应用收到的响应文本，失败JSON/结构尝试也记录，避免后续retry消息修改前一份快照。包含model、temperature、response_format以及辅助RAG调用max_tokens；Transport失败无可用响应时为request_only。生成、Judge、query expansion、LLM query planning、上下文实验等五处chat路径均接入，不保存Authorization/API Key请求头或供应商错误正文。

**回放等级**：redacted_request_response / request_only。保留脱敏规则（含字符串内带引号JSON凭据），不是无限制原始私密文本或逐包HTTP抓取。仍含原SDK空content兼容处理，不记录SDK内部HTTP重试逐包镜像；不保证相同输入重新调用模型会输出相同题目。Embedding/rerank/lifecycle仍原摘要，明确not_requested，不冒称chat完整快照。

### 2.2 默认上限与回收

| 设置 | 现役值 | 语义 |
|---|---:|---|
| TRACE_SNAPSHOT_ENABLED | true | 新应用尝试可封存，不回填历史 |
| TRACE_SNAPSHOT_MAX_BYTES | 1048576 | 脱敏序列化JSON最多1MiB；超过拒存完整载荷而非截断后假称完整 |
| TRACE_SNAPSHOT_TOTAL_BYTES | 134217728 | 全部密文payload累计128MiB；不是整个Postgres/WAL/备份磁盘配额 |
| TRACE_SNAPSHOT_RETENTION_DAYS | 7 | 新快照保存7天；过期读拒绝，bounded maintenance删除密文保留摘要/费用 |

PostgreSQL事务advisory lock串行化配额判定；5真实连接实测只容纳1份时为1available＋4budget_exceeded，五条摘要与成本全保留。每次存档/已有generation maintenance可批量回收最多200过期份；不无限扫描/删除未过期历史。配置缩小配额时停止新增超额，不宣称已经重写所有旧数据。

状态包括available/disabled/not_requested/key_unavailable/oversize/serialization_error/budget_exceeded/capture_failed/expired/legacy_unavailable。加密key缺失、过大或额度不足不隐瞒，也不为了补快照再次请求模型。DB快照失败尽量保留摘要；整个DB故障仍沿原持久spool/严格费用门禁，spool只有摘要，不将遗失完整载荷谎称available。

### 2.3 访问与密钥

/API路径`/api/traces/records/{row_id}/snapshot`：ops:read＋Trace归属检查，服务器解密/验证hash/检查过期后返回脱敏内容，Cache-Control:no-store；成功读取写ConfigAuditEvent（只记录身份/hash/等级，不记录正文）。前端链路展开后可主动点击“查看受限请求／响应快照”，旧记录禁用；页面关闭即移除快照展示，不写localStorage。

独立TRACE_SNAPSHOT_SECRET_KEY，**不复用Provider/JWT key**；已在ignored现有deploy/.env持久配置，四Python服务一致。DB与对应独立key须一起受限备份，错key/丢key返回不可解密，不自动生成新key冒充恢复。原摘要和可选Langfuse只接收截断摘要，不外发完整密文或Prompt。

## 3. few-shot：只消费当前合格的人审样本

### 3.1 正向链路

1. 内容经人工通过或发布后沉淀为SamplePool（原功能）。
2. 样本页“用于 Few-shot”明确把purpose设为fewshot；可改回sft，用途变更按归属校验并审计。
3. [fewshot.py](../../backend/app/engine/fewshot.py)按同题型、同tenant、精确规范化知识点标签取bounded候选；不跨tenant回退、不偷偷调用embedding。
4. 源内容当前passed/published；必须存在同scope的manual_review/100分与实际reviewer；来源要求开启时reference_review.verified必须为true；样本payload与当前内容hash一致，当前JSON Schema／确定性规则再次通过；不同模板/任务scope、目标同批次、stale、待审、无人工、未核验来源均排除。
5. 示范整个对象进入独立[fewshot-instruction.st](../../backend/prompts/fewshot-instruction.st)，与RAG事实资料分开。示例只指导结构/解析，不替代当前RAG来源和生成目标。
6. Trace参数、Graph fewshot_report和QC配置快照保留sample/item/review_record/payload hash/模板版本及排除理由；Judge目标约束不混入示例。逐字复制完整示例输出会触发fewshot_exact_copy并走有限反馈重试，不能靠Prompt一句话保证原创。

参数FEWSHOT_ENABLED=true，最多2例、合计8192字符；**这是额外示例预算，不是总LLM窗口，RAG32768字符另算**。默认最多扫描50候选，可配置200；整体示例超预算就跳过，不切断题干/选项/答案。模板run_config.fewshot可关闭或收紧全局数量/字符上限；坏配置在启动拒绝。客户端不能伪造fewshot_context/provenance，service/旧checkpoint均去除后服务器重新选择。

这不是语义embedding样本检索/专家金标认证，精确标签不同或较老样本超候选池可能不命中；不承诺自动学习或人工驳回率下降。主库sample0，因此当前真实生成会明确0例，不自动把未审核6题转成“优质样本”。

## 4. 已配置模型A/B工具

入口：[model_compare.py](../../backend/scripts/model_compare.py)、[model_comparison.py](../../backend/app/engine/model_comparison.py)。

- 默认只plan，无embedding/chat；档案从数据库读取，不硬编码或自动换现役模型。两个档案同实际端点/模型则ready=false，执行前拒绝无意义收费比较。
- 显式--execute：1～10唯一case；每case来源检索/fewshot只取一次，两候选共享冻结输入hash/模板/source；顺序按case交替A/B、B/A；直接调用所选档案，不因失败暗换默认模型；单候选错误仍留错误类型/费用并继续另一候选。
- 可选--judge-profile：使用已配置的评审档案，报告是否与候选同端点/模型；不同名称也不证明不同模型家族。auto_score是机器信号，human_quality_verdict保持null、human_status为pending。
- 记录生成/质检每次失败的reported usage、token、估算费用、耗时与attempt数；RAG来源费用在run汇总里单独计算共享一次，不把估算当供应商账单。
- 候选输出只入用户指定受限报告与Trace，不进入内容库/样本库，不自动通过/发布，不造专家标注。

当前已用现役lite/high执行plan，实际同一端点/模型，ready=false、executed=false。准备了三条原请求的单选/完形/阅读对比输入，以及从当前10内容导出的10条人工候选（全部candidate、annotations=[]），都只在受限`.local-eval/opt077`。没有执行独立模型收费对比，也不能给出性能/成本“优胜者”。

示意（在backend执行，先配置真实不同档案，输出使用受限路径；本轮未运行execute）：

```powershell

  --profile-a <已配置档案A> --profile-b <已配置档案B> `
  --output ..\.local-eval\comparison-plan.json

# 明确授权实际embedding/chat后才加--execute，并提供cases与可选独立Judge
.\.venv\Scripts\python.exe scripts/model_compare.py `
  --profile-a <已配置档案A> --profile-b <已配置档案B> `
  --judge-profile <已配置评审档案> `
  --cases ..\.local-eval\opt077\comparison-cases.private.json `
  --output ..\.local-eval\comparison-result.private.json --execute
```

后续真实效果必须由用户选定候选并人工评审产物，再按既有[gold_eval.py](../../backend/app/engine/gold_eval.py)的两名人工/争议第三人/版本/有效阈值/payload hash规则建立金标；本轮不能代签human_attested。
