## 2. 状态契约与修复

### 2.1 按对象定义，不强行统一所有名称

| 对象 | 状态 | 语义 |
|---|---|---|
| task | pending / dispatched / running / awaiting_review / succeeded / partially_succeeded / failed / cancelled | 批次调度、运行、人工卡点或执行结束 |
| task item | pending / running / awaiting_review / succeeded / failed / cancelled | 单项执行账本；不再写queued/stored/rejected |
| Graph | stored / rejected / review_passed / review_rejected / awaiting_review / cancelled / failed等 | 工作流结果及中间状态，通过显式映射写item |
| content | pending_qc / awaiting_review / passed / rejected / published | 内容人工审核、发布状态，不等于任务执行状态 |

[status.py](../../backend/app/domain/status.py)成为共享契约：`item_status_from_graph`、`item_status_from_content`和父任务聚合均集中定义。旧Python符号ITEM_QUEUED/STORED/REJECTED仅为兼容别名，其值已指向现役pending/succeeded/failed；真实旧SQL值由迁移定向归一。未知Graph结果不再默认成功，而是永久失败`INVALID_GENERATION_STATE`。

### 2.2 人工等待不是终态

- `awaiting_review`属于活动task与投递保护item，但不是最终完成item。
- 全部item已生成、其中仍有人工卡点时：父task=`awaiting_review`，保留活动防重，不再误报`partially_succeeded`。
- `progress`固定0～1，按**最终执行结果已确定的item数／预期总项数**计算；成功1＋人工等待1显示0.5。人工裁决后重聚合为成功、部分成功或失败。
- 普通`pending_qc`内容仍允许生成task成功；它与Graph interrupt人工卡点不是同一概念。
- 全成功才是succeeded；成功＋取消/失败为partially_succeeded；全部取消为cancelled；失败/取消混合且无成功为failed。显式cancelled父任务不会被迟到完成重新变成succeeded。
- awaiting item不重新生成/派发；人工结果恢复后更新finished_at与父聚合。最终通知只在状态发生转换时触发，并保留原通知幂等保护。
- API TaskOut限定八种状态与0～1进度；SQL task/item检查约束阻止未知或Graph名称混入账本；Repository状态计数移除过时completed口径。
- [TasksPage.tsx](../../frontend/src/pages/TasksPage.tsx)补齐已调度/已取消/等待人工中文标签，列表、进度条、详情均将0.5正确显示50%，而非1%。

投递恢复仍沿用OPT-074有界lease/Outbox/SQL对账，不把等待人工纳入DELIVERY_TASK_STATUSES。人工内容门禁仍沿用OPT-075。

## 3. 并发请求防重

### 3.1 SQL是最终裁决者

新增局部唯一索引`uq_active_generation_request`：对非NULL request_hash、活动状态pending/dispatched/running/awaiting_review建立唯一约束。保留终态相同请求再次生成和旧NULL指纹兼容，不永久锁住历史请求。

[GenerationService](../../backend/app/services/generation_service.py)仍先查询以返回友好提示，但插入/Outbox/提交在同一事务内受SQL唯一约束守卫。只将该指纹唯一冲突翻译为`DuplicateTaskError`/HTTP 409并返回获胜任务ID，其他数据库约束错误不被吞掉；落败请求回滚，不留下第二个task或Outbox。

指纹包含服务端tenant、批次总数、每item归一参数、稳定模板可执行身份和UI route／相关profile hash；不再用启动时可变化的updated_at作为唯一版本依据。启动仅重写时间戳不会绕过防重，模板版本/配置有实质变化可区分。

**应用范围**：新版本提交使用新指纹格式；本次部署前主库活动任务0。旧终态记录不批量重写。将来有旧版本在途任务时，应先停止新提交并排空/核对再升级指纹版本，不能把不同格式hash比较当作完整跨版本语义防重。

死信重放先检查同指纹是否已有另一个活动task，不能为复活历史失败而覆盖当前活动任务；并发极端情况下仍由SQL约束失败关闭，操作人不得绕过索引。

### 3.2 实测

复用原CI PostgreSQL，6个真实连接在查询后barrier同时插入：**1 accepted＋5 duplicate，6个响应引用同一个任务ID，数据库仅1 task＋1 Outbox**。等待人工时重复被拒；转终态后可创建新task。测试仅清理自己的UUID行，不清共享库、不接真实broker。

## 4. 前端Provider与模型配置

### 4.1 用户操作顺序

1. 管理员登录，打开左侧“模型设置”。
2. 新建Provider：自定义名称、OpenAI兼容HTTP(S) Base URL、API Key、启用/禁用。
3. 创建或编辑模型档案：自定义档案名和服务原始模型标识、选择Provider、默认生成降级档案、最大降级次数。
4. 按题型分别选择生成与Judge档案；留空恢复原YAML/环境默认。
5. 如需探测，手动点击“探测模型列表”；不会在保存时自动生成题目或花费生成tokens。Provider可能不支持/models，该探测失败不等于chat一定不可用。

页面：[ModelSettingsPage.tsx](../../frontend/src/pages/ModelSettingsPage.tsx)；API：[model_settings.py](../../backend/app/api/model_settings.py)。沿用App.css已有配色和表单间距，只新增局部几何样式，不引入新色板。

### 4.2 持久化与真实调用

| 实体 | 内容 | 兼容与生效 |
|---|---|---|
| ModelProvider | 名称、base_url、加密凭据、key_revision、配置hash、状态 | 不把凭据放进ModelProfile或Prompt；不绑定者走原ENV |
| ModelProfile | 现有档案＋provider_id/provider_config_hash | 新默认档案按tenant（含NULL）SQL唯一； Provider修改刷新绑定档案hash |
| ModelRoute | 每题型generation_profile/judge_profile覆盖 | 独立于启动同步的YAML，重启不被load_all_templates覆盖 |

生成：[providers.py](../../backend/app/engine/providers.py)根据选中档案实际构建对应OpenAI兼容客户端；[router.py](../../backend/app/engine/router.py)按ModelRoute覆盖→原模板分档→默认档案降级。绑定的Provider不存在/禁用/无法解密不能暗中使用环境密钥向另一端点发请求；按已有生成降级契约可尝试明确默认档案。

Judge：[quality.py](../../backend/app/engine/quality.py)可使用另一档案的模型、Provider与密钥；配置的Judge档案不可用时失败关闭，不暗中改回原Judge。QC快照记录实际Judge模型/档案身份；每次生成与QC Trace记录安全profile/Provider配置身份（不含密钥）。新任务版本快照也含route及profile hash。

`max_fallbacks=0`现在真正表示不降级，不再被`or`当空值覆盖成全局默认。Provider支持手动删除未被引用项；被模型引用时拒删，可禁用；被route引用档案需先解除route才能禁用。

### 4.3 密钥、权限与错误边界

- 模型配置管理为`model:manage`权限，仅管理员；非管理员导航隐藏且API返回403。既有模型档案读取仍按原tenant/共享权限规则。
- Provider凭据使用Fernet加密，独立`PROVIDER_SECRET_KEY`从环境读取，不复用JWT密钥、不写在源码或数据库。已在ignored的现有deploy/.env生成并持久保存，backend/worker/OCR worker/beat保持同一key；值不写进公开报告或Trace。
- 读取只返回has_api_key，不回显明文或ciphertext；编辑留空保留原Key。审计不存密钥；密钥轮换用随机revision改变安全配置身份。
- 请求校验错误不再回显input，避免坏URL/超长key通过422泄露；上游探测/绑定生成或Judge鉴权错误只返回受控类型，测试覆盖供应商错误正文故意包含“secret”的情形。
- Base URL拒绝内嵌user/password、query、fragment和非HTTP(S)协议。HTTP会明文传输请求凭据，公网应使用HTTPS；API未实现公网IP强制HTTPS策略。个人项目允许管理员明确配置本机HTTP端点，**这不是可公开给匿名用户的通用代理**；公网使用需另行安全整改与端点策略。
- 加密key丢失或换错时不可恢复既有Provider凭据；保留原key与DB备份配套，或人工重新输入Provider密钥。不能仅恢复DB便宣称恢复所有自定义模型。

### 4.4 不宣称的能力

本页当前管理chat生成/Judge，不迁移Embedding/OCR配置；不支持非OpenAI兼容的原生协议。固定生成route覆盖会取代该题型难度分档，留空才恢复YAML分档。自定义模型成本仍走后端PRICE_MAP/全局单价估算，不抓取实时价格，不是供应商账单。保存后供后续调用使用；完成内容不重跑，运行中后续节点可能采用新配置，建议静默窗口改动。
