## P2 风险与维护项

- 样本池当前只沉淀和导出，不自动参与 few-shot 或训练；需要离线实验后再接入生成链路。
- 当前没有 Playwright 的完整浏览器验收，前端构建通过不等于登录、生成、审核、发布交互全部可用。
- 当前没有并发、吞吐、限流、队列积压和成本上限基线；`MODEL_BUDGET_PER_TASK=0` 表示默认不启用任务级预算。
- 工作区残留的 `routes_*.py`、备份文件和临时脚本会干扰本地静态检查，并可能进入 backend Docker build context；应清理或更新 `backend/.dockerignore`。
- 生产环境要确认数据库备份、恢复库、Langfuse 数据库、Redis 持久化和密钥轮换的责任人及操作手册。

## 建议的验证顺序

1. **待用户恢复数据库测试后再验证真实运行环境**：配齐非占位密钥，启动 Compose，执行 Alembic，确认 `/api/health/ready`，并确认 checkpointer 为 PostgresSaver。
2. **再验证可靠性**：用真实 Postgres/Redis 跑全量测试；模拟 worker/API 重启、Outbox dead/replay、任务取消、人工卡点恢复和重复投递。
3. **回验已修复质量硬缺口**：P0-1 至 P0-5 已通过纯单测；待真实迁移/模型和固定金标集复验。
4. **建立首版金标集**：每类题型先做小规模分层集，输出答案/解析/多解/知识点/难度指标和人工驳回率。
5. **最后再做规模验证**：固定模型和模板版本，压测 10、50 条任务，以及两批各 50 条的并发任务（单模板数量上限仍为 50），记录成功率、P95 延迟、重试率、单题成本和队列积压。
