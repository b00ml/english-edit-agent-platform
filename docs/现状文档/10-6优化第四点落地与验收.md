# 10-6优化第四点：确定性题目校验落地与验收

> 日期：2026-10-06（Asia/Shanghai）；阶段：OPT-075。范围依据原[10-6优化文档](10-6优化文档.md)第四点，不扩展并发去重、状态命名、独立Judge、Trace完整快照或few-shot。

## 1. 结论与边界

**第四点中的可确定性判断问题已落地、迁移、部署并验收；不宣称已自动解决语义错误或多解。**

- 完形每空、单选每题、阅读每小题：恰好四个非空、非重复选项；答案统一A/B/C/D，依次映射options数组位置。
- options仅存正文，不含`A.`等序号前缀；答案不得使用词语、带标点序号或混用大小写/空白形式。旧输出不静默修正或重排。
- 完形blanks非空；index必须按数组顺序从1连续递增、不重复；passage中`____`数量与blanks一致，不混用其他下划线长度。
- 同一道语篇内至少5个小题的答案全部位于同一位置，会给出位置偏置告警；阈值配置可调整。它不是硬失败，不要求短批次平均，也不是跨批次统计检验。
- 程序不判断英语题的正确答案是否符合原文、不证明答案唯一性；连词语义/多种合理解释仍必须人工核验。

## 2. 根因与实现

### 2.1 配置驱动的规则

原完形Schema仅约束字段类型，不能充分排除错空数、重复索引、混用答案表示。三种模板均升级到version 3，JSON Schema补齐长度/枚举/数组数量等约束，`run_config.content_validation.choice_sets`声明通用跨字段规则。

```yaml
content_validation:
  choice_sets:
    - path: blanks
      index_field: index
      passage_field: passage
      blank_marker: ____
```

单选path为空表示根对象，阅读path为questions；自定义题型可声明点分隔集合路径、options_field、answer_field、labels、index_field、passage_field，无需Python按题型名称分派。规则配置启动时校验，拼写错误不能静默忽略。

实现：[content_validation.py](../../backend/app/engine/content_validation.py)、[template_loader.py](../../backend/app/template_loader.py)。重复项判定仅对诊断用副本做NFKC/空白/大小写归一，**不修改选项原文**；它不能识别所有近义词或语义等价。

### 2.2 接入生成、断点、审核与发布

| 入口 | 现在执行的动作 | 失败语义 |
|---|---|---|
| 结构化生成 | 原始归一结构先过JSON Schema，再经Pydantic、完整Schema、跨字段规则 | 错误按字段/规则反馈到已有有限重试；每次尝试计Trace/usage/cost；耗尽失败关闭 |
| Graph validate | 完整Schema与规则重新检查 | invalid进入有界revise，反馈包含具体确定性错误；预算耗尽reject，而不是无限generate |
| Graph QC、store、submit_review | 各自再校验，包括旧checkpoint/已完成QC缓存路径 | 坏草稿不能凭99分进入Judge或待审库 |
| 人工审核通过 | 使用现役模板重查，包括直接恢复human_review节点 | HTTP 409或图失败；不写通过记录；坏题仍允许人工驳回 |
| 发布 | 即使历史状态为passed，也执行现役规则 | 不允许因历史高分或旧人工状态绕过当前硬约束 |
| 内容列表/详情 | 只读重新计算当前规则诊断，批量加载模板，返回validation_report | 旧题问题立即可见，不回写历史payload/score/status；缺失模板不能通过/发布 |

生成引擎：[structured_output.py](../../backend/app/engine/structured_output.py)；图：[graph.py](../../backend/app/workflow/graph.py)；审核/发布共享门禁：[content_guard.py](../../backend/app/services/content_guard.py)。错误类集中在[errors.py](../../backend/app/errors.py)，提供`CONTENT_VALIDATION_FAILED`。

### 2.3 独立诊断与前端

新增ContentItem.validation_report可空JSONB，保存errors/warnings/valid/semantic_verification，与payload、RAG provenance分开。迁移：[opt075_content_validation.py](../../backend/alembic/versions/opt075_content_validation.py)，head=`opt075_content_validation`，仅新增列，不批量改旧题。

新生成内容保存当时诊断；QC配置快照和成功生成Trace输入也保留诊断。列表/详情的报告是**现役规则的只读诊断**，不等于更改历史模型评分或专家裁决。`semantic_verification=requires_human_review`描述规则不证明语义，实际人工决定仍看manual_review记录及内容状态。

[ContentPreview.tsx](../../frontend/src/components/ContentPreview.tsx)显示结构错误、答案位置偏置以及语义复核提醒；[QualityPage.tsx](../../frontend/src/pages/QualityPage.tsx)对确定性失败禁用通过，仍可驳回；[ContentLibraryPage.tsx](../../frontend/src/pages/ContentLibraryPage.tsx)只允许passed且当前诊断不失败的内容发起发布。服务器独立执行同样门禁，不依赖按钮安全。

### 2.4 修正Prompt口径

完形旧Prompt写“每篇空格数与数量参数一致”，与OPT-074单执行项quantity=1冲突。现在明确quantity是篇数，不是空格数；一篇可有多个空，空数对应blanks。三题型Prompt与Skill同步规范答案/选项正文、干扰项逐一排除及语义复核。不会静默乱序或把短篇强制成单空。
