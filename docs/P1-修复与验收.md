> 2026-10-04；P1 九项代码修复与本地回归已交付。系统解释器测试 365 passed / 8 skipped；不启动 Docker，不执行真实 PostgreSQL/Redis/供应商/账单测试。P0 真金标与跨进程恢复仍未关闭。

## 1. 权限与历史数据

- admin 是全局管理员，不是某租户管理员。其他角色只能操作本租户资源；`tenant_id=None` 为默认租户 `IS NULL`，不是全量权限或“未分配”。创建用户时需明确这是默认租户成员还是具名租户成员。
- viewer 只读本租户已发布内容，不能查看任务参数/链路。共享 Null 模板/模型可读；知识资料不因此共享。
- 通知是租户广播，已读状态也共享；未实现按用户独立 inbox。
- 提交参数中的 tenant_id 不作为归属来源；worker 从任务行覆盖它。全局管理员审核别人的内容时，人工质量记录仍归内容租户，reviewer 单独记录操作人。
- 校准按目标租户；全局管理员可显式提交 CalibrateRequest.tenant_id（包括 null），普通用户不能跨 scope。版本/时间窗训练分层仍未完成。
- 新迁移只回填可由 task/content 推导的缺失归属；非空冲突需人工审计，拒绝盲目转移；旧知识/校准无可靠来源时不猜测归属或自动共享。

## 3. 模型配置

```dotenv
MODEL_PROFILE_MODELS={"lite":"填写实际模型","standard":"填写实际模型","high":"填写实际模型"}
REQUIRE_DISTINCT_MODEL_TIERS=false
REQUIRE_INDEPENDENT_JUDGE=false
JUDGE_MODEL_NAME=填写实际评审模型
JUDGE_API_BASE=
JUDGE_API_KEY=
```

上面仅是字段格式，不是模型推荐或可用性证据。首次/缺失档案使用映射；已有数据库管理员配置不会被环境变量覆盖，更新已有模型须使用受权模型档案 API。未配置映射时仍回退默认模型并警告；两个策略设 true 时启动拒绝相同模型名。名称不同不能证明不同家族、能力或效果。

题型 YAML model_profile 的难档键现在与输入枚举“难”一致。Judge endpoint/key 可独立提供，否则回退 LLM endpoint/key。不要把 Key 写进 YAML、Prompt、账单或仓库。

## 4. RAG 与人工来源核验

全局 RAG_MODE 支持 off/optional/required，RAG_MIN_SIMILARITY 默认 0.3。模板可覆盖：

```yaml
run_config:
  rag:
    mode: required
    require_human_verification: true
```

- optional 的检索失败降级继续，但明确记录 degraded；required 无有效来源失败关闭。开启 require_human_verification 会要求有效来源，而不是允许空资料“核验”。
- 记录来源 chunk ID、名称、文本快照、hash、相似度和 hit/no_match/degraded；题目输出 Schema 不混入平台 metadata，provenance 单独保存。
- 质检页可以阅读当时的来源文本，勾选“已核对”后提交 reference_verified。服务端检查来源记录非空及声明、留 reviewer，发布再次检查；核验基于生成时文本快照，不宣称当前知识块仍存在或自动核对答案。
- 这是人工责任声明，不是机器证明答案事实正确。实际金标仍需双人标注/仲裁；gold_report 增 by_rag_status，历史无记录为 unknown。
- 文本/文件上传走同一知识服务；每份资料、列表、检索、删除均按租户。Embedding 维度必须与数据库 Schema 一致，不自动改 pgvector 字段。

## 5. 失败、重投和告警

- 连接/超时和结构化 HTTP 408/429/5xx 是可重试；400/401/403/404/422 与质量/结构耗尽等为终态。
- 解包路由 last_error，不分析错误文本里的数字；未知异常失败关闭。重试耗尽设置 failed、failure_code，并聚合父任务/站内通知；不会永久留 running。
- 这些纯单测不证明真实 broker、worker kill/restart 或供应商限流行为。待恢复环境测试后按 P0 恢复手册再验。

## 6. CORS/网络配置

```dotenv
CORS_ALLOWED_ORIGINS=["http://localhost:3000","http://localhost:5173"]
CORS_ALLOW_CREDENTIALS=false
BIND_ADDRESS=127.0.0.1
```

默认回环端口；LAN 暴露必须显式改变绑定与允许来源，远端域名需自行配置 HTTPS/反向代理。生产/staging 禁止 origins 通配符，任何环境凭据模式也禁止通配符。Bearer 权限是服务端边界，CORS 不是认证控制。本轮没有运行浏览器或 TLS/LAN 测试。

## 7. Trace 补偿与健康

```dotenv
TRACE_REQUIRE_DURABILITY=true
TRACE_FAILURE_SPOOL_DIR=/持久化补偿目录
```

Compose 给 API/worker 配了各自持久化卷；本轮未验证真实卷。正常写库；失败时写已脱敏 JSON，文件同步后原子切换，稳定 id 支持幂等补投。严格模式下 DB/补偿同时失败会拒绝静默丢失。不可恢复丢失会保留当前进程告警，后续一次成功不能证明历史记录已恢复；须人工核对后才处理运行状态。

```powershell
# backend/；在配置相应数据库和补偿目录的进程环境执行，本轮不运行真实补投
python scripts/replay_trace_spool.py --limit 100
```

`/api/trace-health` 为当前 API 进程及其目录的诊断；API 与 worker 目录/进程独立，要分别监控/补投。它不是全 worker 集群监控，也不证明任意硬杀/断电期间绝不丢记录。pending 日志费用计入预算，无法读取 pending 时预算检查失败关闭。

未知 usage/历史单价分量不伪装提供商报告 0；输入/输出费用按当时估算值保存，不按新全局费率重算历史。账单仍是供应商权威来源。

## 8. 规范化账单比对

操作者先将账单映射为与 Trace 相同币种、相同完整调用窗口的 trace_id/billed_cost CSV。供应商未提供可关联信息时不要虚构映射；该工具不自动抓账单、换算币种或推断请求 ID。

```powershell
python scripts/reconcile_costs.py --bills normalized-bill.csv --currency CNY --output comparison.json
```

只读数据库，输出 matched/mismatch/missing_trace/missing_bill 及 unknown_usage；未知数据或差异不会作为通过返回。数字比较正确不等于供应商金额已验证。本轮只用合成 CSV 测试。
