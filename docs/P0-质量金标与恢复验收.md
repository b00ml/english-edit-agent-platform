> 日期：2026-10-04。P0-1～5 已通过纯单测，P0-6（真实人工金标）和 P0-7（真实 PostgreSQL 跨进程恢复）尚未完成验收。本轮不启动 Docker、不调用真实模型。所有测试 fixture 都是合成数据，不属于教研金标。

## 1. 先区分环境

- 本轮系统 Python 3.12：`PYTHONPATH=.` 后 `python -m pytest -o addopts="-q"` 得到 `287 passed, 8 skipped`。
- 仓库 `.venv` 可以运行 Alembic 离线 SQL，但缺少 PyJWT/passlib/bcrypt/psycopg 等已有生产依赖，不能把它当成完整测试环境。本轮没有安装/修改该环境。
- 在准备真实验收时，选定独立虚拟环境，从 `backend/requirements.txt` 与 `requirements-dev.txt` 安装依赖，再执行测试；不要把测试连到业务生产数据库。

```powershell
# 在 backend/ 下；此命令为后续环境准备说明，本轮未执行安装
python -m pip install -r requirements.txt -r requirements-dev.txt
$env:PYTHONPATH = "."
python -m pytest -m "not integration" -o addopts="-q"
```

## 2. 真实数据库迁移前置条件（本轮不执行）

1. 备份业务库，恢复到独立验证库；迁移只先作用于验证库。
2. `python scripts/migration_precheck.py` 会检查数据库、迁移单 head 和重复非空内容 thread_id。重复记录须先人工核对，不能静默删历史内容。
3. 确认新迁移链为 `m3_03_model_hash → p0_04_quality_events → p0_07_thread_unique`，在验证库执行 `alembic upgrade head`。
4. 新增 `quality_evaluation`（每 thread/改版轮次唯一），以及 `content_item.thread_id` 唯一约束。旧正常入库内容的 thread_id 可能为空；不推断、不伪造历史首过分母或金标。
5. 本轮只用 `.venv/Scripts/python.exe -m alembic heads` 与 `upgrade head --sql` 验证单一 head 和 SQL 生成，未验证实际 DDL。

## 3. 导出待人工复核的候选

在已部署、已迁移且存在真实生成内容的数据库上，显式配置 DATABASE_URL 后执行。文件必须为新路径；工具使用排他写入，拒绝覆盖既有题集或报告。

```powershell
# backend/ 下；需真实业务数据，本轮未执行
python scripts/quality_gold.py export --dataset-version gold-2026-10-v1 --limit 100 --output candidates-v1.jsonl
```

候选保存原 payload、payload_hash、当轮冻结生成约束、自动分/有效阈值及模板、生成 Prompt/Skill、实际生成模型、Judge 模型/Prompt/Skill 版本。缺少完整 Trace/版本的历史候选可以人工排查，但不能直接设为 reviewed 获得可信报告。导出目前是创建时间排序，不是随机抽样；报告只能描述标注集合，不能外推全部产出的正确率。

## 4. 人工标注规则

每条候选：

- 保持 case_id、dataset_version、payload、payload_hash、params、versions、auto_score、threshold 不变。
- 由两位不同的真实教研人员独立复核；`annotations` 恰好有两条，填入 reviewer、`human_attested: true`、payload_hash、annotated_at（带时区 ISO 时间）。
- 每人判断 answer_correct、explanation_correct、unambiguous、knowledge_match、difficulty_match，必须使用 JSON 布尔值。
- 填 expected_answer（单项 string，多空/多小题 list of strings）及 evidence（依据/错误解释，禁止空白说明）。
- 任一判定或 expected_answer 有争议，必须添加独立第三人的 `adjudication`，字段与 annotation 相同。仲裁人不能与原标注者相同。
- 完成后把 status 从 candidate 改为 reviewed。机器校验的是人工声明及数据完整性，不认证人的真实身份，也不代替复核流程。

标注字段骨架（占位说明不是有效金标，必须由真人填写）：

```json
{
  "reviewer": "真实审核者标识",
  "human_attested": true,
  "payload_hash": "复制该候选的64位hash",
  "annotated_at": "2026-10-04T16:00:00+08:00",
  "answer_correct": true,
  "explanation_correct": true,
  "unambiguous": true,
  "knowledge_match": true,
  "difficulty_match": true,
  "expected_answer": "经人工核对的正确答案",
  "evidence": "具体语法/语篇依据及争议说明"
}
```

## 5. 离线报告

```powershell
python scripts/quality_gold.py report --input reviewed-v1.jsonl --output report-v1.json
```

工具无模型调用，输出数据集 hash、样本量、题型/难度分层、每题版本、混淆矩阵、precision/recall/F1、kappa、自动放行中的答案/解析错误率、多解率和人工驳回率。不同阈值逐题判定；同一 dataset_version 内可比较配置，但报告显式保留各题版本。小于 30 条会提示样本不足；退化单类 kappa 返回 null。无自动放行样本时相关错误率也返回 null，不伪装成 0。

**准入证据**：冻结题型/难度/知识点分布和来源；保留独立标注与仲裁记录；用固定样本集比较修改前后。不得使用测试 mock、仅 auto 高分样本或仅疑难样本证明整体 ≤5% 驳回率。

## 6. 跨进程恢复验收（用户恢复数据库测试后再执行）

新增 `tests/integration/test_persistent_recovery.py` 使用真实 PostgresSaver 和至少两个独立 Python 子进程，覆盖：

1. 完成后另一进程重放：生成只调用一次、只入一条内容。
2. 生成已保存、qc 前故障：下一进程从 checkpoint 继续，不再次生成。
3. 灰区 interrupt：另一进程完成人工裁决，再重放，不重复生成或人工记录。

```powershell
# 必须是独立的 pgvector 测试数据库，不要填生产数据库
$env:TEST_DATABASE_URL = "postgresql+psycopg2://..."
$env:PYTHONPATH = "."
python -m pytest tests/integration/test_persistent_recovery.py -o addopts="-q"
# 随后验证原有业务 API 闭环（LLM/embedding 为 mock，child job 在进程内执行）
python -m pytest tests/integration/test_pipeline.py -o addopts="-q"
```

测试仅替换 LLM/RAG，不把 MemorySaver 当作持久化证明；子进程断言实际 saver 为 PostgresSaver。它不需要 Docker，也不证明真实 Celery broker 重投、worker kill/restart 或供应商可用性。最终再在真实部署安排 Celery/Redis 故障演练并记录现场证据。
