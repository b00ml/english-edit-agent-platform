## 1. 这一层解决什么问题

主文档回答“现在如何工作”，五专题回答“模块具体如何实现”；本层回答：

- 为什么从原链路走到当前实现？
- 某项能力何时是计划、何时有代码、何时真正部署/使用？
- 一条通过、失败或待验证结论出自哪个报告、样本、配置和日志？

## 6. 资产清单如何使用

本次登记 **341个原位文件**：41份仓库文档/许可资料，300个私有本机证据；索引73个OPT章节。每个asset有：

- asset_id（A001等，本次清单定位用，不是业务ID）；
- absolute path与repository_relative_path；
- stage、role、visibility；
- available_at_audit、bytes、文件字节SHA-256；
- proof_scope：仅证明整理时存在/身份，body_copied=false。

资产ID依赖本次清单，后续不要假定重新排序仍保持相同ID。`change_log_records`保留OPT原heading、日期原文、源文件及行范围；行号按UTF-8读取后的LF换行计数（旧记录里的form-feed字符不作为换行），必须和源文件hash一起使用；后续修改可移动行。

不是递归扫整机：OCR目录仅选报告/样本/后台/工作台/召回等已知子目录，不扫venv、模型cache、宿主机私有文件；不登记helper执行脚本或账户环境文件。按名称排除了9项鉴权/登录态/进程等文件，另未登记endpoint配置；**名称排除不是完整secret扫描认证**。

数据库dump、原结果和截图也可能敏感，清单只登记路径/hash，不复制它们，不将其从Git忽略目录搬出。本层的JSON不包含原报告正文、模型prompt/payload、账户口令或token值。

## 7. 什么有证据，什么只有报告

| 标记 | 意义 |
|---|---|
| 文件存在且已hash | 本机原位资产可定位，整理时摘要可核对 |
| 已核对日志/结构化结果 | 本轮读取既有结果进行交叉检查，未重执行 |
| 报告声明，底层独立日志未定位 | 有原阶段记录，但本轮不足以做独立结果证明 |
| 设计/能力声明 | 可理解目标或代码存在，不宣称运行效果 |
| 被后续替代 | 原结论在当时有效，默认值/范围/协议后来已变 |
| 未验收 | 现有材料不足或明确保留待验证 |

P0/P1早期底层临时证据有的在外部临时目录、有的只有报告说明；本清单不凭文档中一个路径就声称它现在仍存在，也不为缺失文件制造日志。可用性按本次实际盘点，未盘点的外部路径标为未核对。

## 8. 原位保留与分享规则

- 不移动、不重命名、不删除旧报告和`.local-eval`现场。
- 公开分享优先主文档、专题、脱敏的阶段说明；检查个人路径/业务ID是否需要进一步删减。
- 清单有本机路径，公开仓库clone通常不能直接打开私有证据；不承诺无需凭据可公开重跑全部案例。
- DB备份不是恢复通过证据；browser-state存在也不是浏览器测试通过证据。
- 将来若获授权清理，先记录哪些结论会失去底层复核材料；不能只保留截图而删掉gold/配置/实际结果再称可复现。
